# `src/server/`: the business core

Everything the admin screens and the on-demand APIs do with data goes through the modules in this folder.
Pages and endpoints stay thin: they read the form or the request, call ONE function here, and redirect or render
the result. Nothing in this folder renders HTML.

Design: `admin-portal-design.md` §2–§3, as changed by `admin-portal-amendments.md` (A1–A6). Both files sit outside
the repo; the amendments win.

| File | What it holds |
|---|---|
| `db.ts` | D1 types, `Result` / `Failure`, `Actor`, `Effects`, query helpers, `versionedUpdate`, `auditInsert`, `uuid`, `now` |
| `time.ts` | UTC storage format, IST days / months / financial years |
| `settings.ts` + `settings.defaults.mjs` | the `settings` table: defaults, validation, saving, version bumps |
| `catalog.ts` | D1 → the catalog format (`/api/catalog.json`), the `/api/live.json` payload, the batch lookup |
| `../lib/availability.ts` | pack availability from a stock pool (contract 7), kg formatting and parsing |
| `stock.ts` | pools, harvests (+ batch), counts, adjustments, tracking, low level, availability override, batches, alerts |
| `orders.ts` | order reading / search / lists, manual and pasted orders, lines, charges, customer, payments, every status step, invoices, test data |
| `intake.ts` | the public `POST /api/orders.json` body check and storage (contract 3) |

## 1. Conventions every function follows

- **Shape.** Writes are `fn(db, actor, input, at?) → Promise<Result<T>>`. Reads are `fn(db, …) → Promise<T>`.
  - `db` is the D1 binding (`env.DB`). Functions that also need KV or the deploy hook take an `env`-like object
    instead (`{ DB, MEDIA }`, `{ DB, BACKUPS }`, `{ DB, DEPLOY_HOOK_URL }`); pass the Worker's `env` itself.
  - `actor` is `Astro.locals.admin` (`{ email, role: 'owner' | 'helper' }`). Jobs use `SYSTEM`.
  - `at` is the current time (`'YYYY-MM-DDTHH:MM:SSZ'`, default `now()`). Pass it only in tests.
- **Results, never exceptions, for anything a person can cause.**
  ```ts
  type Result<T> = { ok: true; value: T } | Failure;
  interface Failure { ok: false; error: ErrorCode; message: string; field?: string; details?: unknown }
  type ErrorCode = 'not_found' | 'conflict' | 'invalid' | 'needs_price' | 'needs_restock_answer' | 'forbidden' | 'not_allowed';
  ```
  - `message` is plain English for the owner; show it as it is.
  - `field` names the form field it belongs to (`'line-3'`, `'discountPaise'`, `'batch.code'`, `'pool-12'` …).
  - `conflict` covers "someone else changed this" (version), "already in that state", a used code, a repeated
    form key. The page should re-read the row and show the message.
  - A real D1 failure (database down, a bug) is thrown as `DbError` (`kind: 'unique' | 'check' | 'foreign_key' |
    'not_null' | 'other'`). Let it reach the error page.
- **Versions.** Every editable row has `version`. Forms carry the version they were rendered with and pass it back;
  a stale version is `conflict`. A successful write returns the new `version`.
- **One write = one D1 batch** (a transaction). The first statement changes the row only if its status and version
  still match and stamps a fresh op token (`orders.last_op`); every later statement is guarded by that token, so a
  rejected first statement turns the whole batch into a no-op. The audit row is written in the same batch.
- **Form keys (`idemKey`).** Forms that create something (a manual order, a payment, a harvest, a count, an
  adjustment) should carry a hidden random key (`crypto.randomUUID()` when the form is rendered). A double tap then
  makes one row: the second call returns `duplicate: true` (orders, payments) or `conflict` (stock).
- **Money** is integer paise everywhere (`₹310` = `31000`). Format with `formatINR()` from `src/lib/money.ts`.
- **Times** are stored as UTC text `YYYY-MM-DDTHH:MM:SSZ`. Days, months and financial years are IST (`time.ts`).
- **Stock** is counted per pool (A3): grams for honey (shown as kg), pieces for candles and sticks. A pack uses
  `pool_qty` of its pool. Amounts are never published.
- **No personal data in audit rows.** Customer fields are written to the order only; the audit says "Customer details
  or note changed".

### 1.1 Effects: what a write means for the website

Writes that can change the public site return `effects`:

```ts
interface Effects {
  publish: 'now' | 'scheduled' | null;  // 'now': site_version was bumped → call requestPublish (handleEffects does it)
                                        // 'scheduled': publish_due_at was set (+30 min); the cron publishes
  live: boolean;                        // live_version was bumped: /api/live.json shows it within about a minute
}
```

After a successful write, call `handleEffects(env, ctx, actor, result.value.effects, reason)` (publish.ts). It does
nothing unless `publish === 'now'`, and it never waits for the build.

### 1.2 Calling a function from an admin page

```astro
---
// src/pages/admin/orders/[id].astro
export const prerender = false;
import { env } from 'cloudflare:workers';
import { confirmOrder, getOrder } from '../../../server/orders';
import { handleEffects } from '../../../server/publish';
import { toId } from '../../../server/db';

const admin = Astro.locals.admin!;
const id = toId(Astro.params.id);
if (!id) return new Response('Not found', { status: 404 });

if (Astro.request.method === 'POST') {
  const form = await Astro.request.formData();
  if (form.get('_action') === 'confirm') {
    const r = await confirmOrder(env.DB, admin, { id, version: Number(form.get('version')) });
    if (r.ok) {
      const ctx = (Astro.locals as { cfContext?: ExecutionContext }).cfContext;
      if (ctx) await handleEffects(env, ctx, admin, r.value.effects, 'Order confirmed');
      // flash: r.value.negative → "Stock is now −0.5 kg for Murungai Honey, recount soon"
    } else {
      // flash r.message (and r.field); for 'needs_price', r.details lists the lines without a price
    }
    return Astro.redirect(`/admin/orders/${id}/`, 303);
  }
}
const detail = await getOrder(env.DB, id);
---
```

### 1.4 D1 limits that the Node test shim also enforces

D1's SQLite is stricter than a default SQLite (checked against workerd's D1):
- a `LIKE` / `GLOB` pattern may be at most **50 bytes** (also inside CHECK constraints; error "LIKE or GLOB pattern
  too complex"). Use `instr()`, `substr()` or `=` for user text; this is why name search uses `instr(lower(…))`.
- a compound `SELECT` (`UNION` …) may have at most **5 terms**;
- at most **100 bound parameters** per statement (pass lists as one JSON parameter: `IN (SELECT value FROM json_each(?))`);
- named parameters do not exist (use `?` or `?NNN`), `undefined` cannot be bound.

## 3. `db.ts`

```ts
interface D1 { prepare(sql): D1Statement; batch(stmts): Promise<D1Result[]>; exec(sql): Promise<{count, duration}> }
interface Actor { email: string; role: 'owner' | 'helper' }
const SYSTEM: Actor            // { email: 'system', role: 'owner' }: cron jobs
const PUBLIC_ACTOR = 'public'  // updated_by of website orders until the owner edits them
const NO_EFFECTS: Effects      // { publish: null, live: false }
```

| Function | Does |
|---|---|
| `now(): string` | current UTC time in the storage format (alias of `time.nowIso`) |
| `uuid(): string` | `crypto.randomUUID()` (op tokens, keys) |
| `ok(value)`, `fail(code, message, { field?, details? })` | build results |
| `ownerOnly(actor): Failure \| null` | `forbidden` for helpers |
| `stmt(db, sql, ...params): D1Statement` | prepared and bound |
| `first<T>(db, sql, ...params): Promise<T \| null>` | first row |
| `all<T>(db, sql, ...params): Promise<T[]>` | all rows |
| `run(db, sql, ...params): Promise<D1Meta>` | one write; `meta.changes`, `meta.last_row_id` |
| `batch(db, stmts): Promise<D1Result[]>` | one transaction; throws `DbError` on a constraint failure |
| `tryBatch(db, stmts, messages?): Promise<Result<D1Result[]>>` | as `batch`, but a UNIQUE failure → `conflict`, CHECK / FK / NOT NULL → `invalid` (other errors are thrown) |
| `orderOpGuard(orderId, op): Guard` | `EXISTS (SELECT 1 FROM orders WHERE id = ? AND last_op = ?)` |
| `versionedUpdate(db, { table, key: [col, value], version, set, actor, at, guard? }): D1Statement` | `UPDATE … SET …, version = version + 1, updated_at, updated_by WHERE key = ? AND version = ?`; check `meta.changes === 1` |
| `auditInsert(db, { at, actor, action, entity, entityId, summary, before?, after? }, guard?): D1Statement` | one audit row; with a guard it is written only when the guard holds |
| `placeholders(n): string` | `'?, ?, ?'` |
| `toId(v): number \| null` | positive whole number from a form or URL value, else null |

```ts
const s = versionedUpdate(env.DB, { table: 'stock_pools', key: ['id', 3], version: 4, set: { low_at: 2000 }, actor: admin, at: now() });
const [r] = await batch(env.DB, [s, auditInsert(env.DB, { at, actor: admin, action: 'stock.low_level', entity: 'pool', entityId: 3, summary: 'Murungai Honey: low-stock level changed' })]);
if (r.meta.changes !== 1) { /* someone else changed it */ }
```

Rules (A3):
- A harvest makes one `harvests` row, one `harvest` move and (unless `batch: false`) one batch: code suggested
  `<SHORT>-<YYMM>-<NN>`, packed on the harvest date, best before +24 months, public. Harvests are for gram pools.
- The first harvest or count switches tracking on. If the pool was never tracked (`tracking_since IS NULL`), a `count`
  move first brings the ledger to 0, so orders confirmed before tracking are never subtracted again (also for
  `setTracking` on). A pool tracked before and switched off keeps its ledger: a harvest adds to it.
- A count writes `typed − current` (worked out inside the batch, so a sale confirmed meanwhile is not lost).
- Adjustments do not switch tracking on. Negative stock is allowed.
- Helpers may harvest, count, adjust, set tracking and low levels; only the owner sets the availability override.

Lower-level helpers used by `orders.ts` (and available to new writers): `readPoolForecasts`, `forecastStatusChange(db, Map<poolId, PoolChange>)`,
`changesPublicStatus(before, change, display)`, `stockStatusStatements(db, at, by, guard?)`, `recomputePoolsStmt(db, poolIds, guard?)`.

